# Phase 7 — AI Skills + Agent Instructions: Design

**Date:** 2026-07-07
**Status:** Approved for implementation planning
**Reference model:** Cairno repo (`~/Documents/Addey-The-Dev/Cairno/Project-Cairno`) — its `AGENTS.md` protocol shape and `.agents/skills/` layout are the proven patterns this design adapts.

---

## Goal

Make Svelocity Stack repos — both this reference repo and every project generated by
`create-svelocity` — safe and productive for AI coding agents. Ship `AGENTS.md`, one
Cursor rule, and five bundled skills, wired into the manifest and CLI.

## File Layout

New files in the stack repo. Everything ships into generated projects except where
marked excluded.

```text
AGENTS.md                              # single source, generated-project voice, tokenized
.cursor/rules/svelocity.mdc            # ~10 lines, alwaysApply pointer
.agents/
  README.md                            # platform discovery + bundled + recommended skills tables
  skills/
    svelocity-convex/SKILL.md
    svelocity-auth/SKILL.md

    svelocity-alignment-audit/

    svelocity-changelog/
      SKILL.md

      changelog-template.md
.claude/skills/<name> -> ../../.agents/skills/<name>   # symlinks, created at scaffold time

```

## Template Mechanics

Three changes to `packages/create-svelocity/scripts/build-template.mjs` and the
`create` command:

1. **`.claude` stays excluded** from the snapshot (`EXCLUDE_DIR_NAMES`) — it contains
   worktrees and session junk, and snapshotting symlinks is fragile.
2. **`create` generates the symlinks post-scaffold**: read `.agents/skills/*`
   directories in the generated project, symlink each into `.claude/skills/<name>`.
   Fallback: if `symlink()` throws (e.g. Windows without developer mode), copy the
   directory instead and note it in the CLI output.
3. **Add `docs/CONTRIBUTING-STACK.md` to `EXCLUDE_PATHS`.** Verify `.cursor` and
   `.agents` are NOT excluded (today only `.claude` is).

`AGENTS.md` participates in the existing token-replacement system (project name).

## AGENTS.md Content

Cairno's ordered-protocol structure, mapped to Svelocity:

```markdown
# AGENTS.md
> None of these steps are optional. Complete them in order.

## Before You Start Any Task
1. Read docs/CONVENTIONS.md — naming, layout, dependency direction
2. Read docs/DEMO-SPEC.md if touching the Shared Tasks demo
3. UI work → read packages/theme/README.md + packages/ui/README.md (tokens, components)
4. Ask intent questions if the task is vague, before writing code

## After Every Change
1. pnpm check && pnpm test before declaring a task complete
2. Update CHANGELOG.md via the svelocity-changelog skill (user-facing changes)
3. Commit only with user permission; conventional commits

## Foundational Stack
# table: Svelte 5 (runes) / SvelteKit 2 / Bits UI / Convex + Convex Auth /
# pnpm workspaces + catalog / adapter-cloudflare / Electron / Capacitor

## Architecture Rules
# the 5 hard rules:
# - business logic lives in packages/app-core, never in apps
# - shared UI lives in packages/ui, never duplicated per app
# - apps are thin platform shells
# - no cross-app imports — apps import packages only
# - no packages importing from apps

## Prohibited Shortcuts
# no `any` without comment, no business logic in UI components,
# no bypassing auth guards, no secrets in client bundles,
# no disabling Electron contextIsolation

## Asking Intent Questions
# Cairno's format, adapted

## Skills
# table of the 5 bundled skills + pointer to .agents/README.md
# for recommended external skills

## Architecture Review / Auth Review
# sections replacing sub-agents (phase spec 7.8)
```

## .cursor/rules/svelocity.mdc

`alwaysApply: true`. Body: "Read AGENTS.md before any task" + the 5 architecture
rules verbatim. Nothing else — one file, no drift surface.

## .agents/README.md

- **Platform discovery table** — how Cursor, Claude Code, and Codex each find skills
  (Cairno's table, adapted).
- **Bundled skills table** — the 5, one-line purpose each.
- **Recommended skills table** — not bundled, one-line install path each:
  - `caveman` — plugin marketplace install command
  - `impeccable` — vendor-copy into `.agents/skills/` + symlink
  - Convex upstream skills — `npx convex ai-files install`
- **Adding a skill** — create under `.agents/skills/<name>/`, symlink into
  `.claude/skills/<name>`.

## The Five Skills

All skills use Cairno-style frontmatter: `name`, `description` with concrete trigger
phrases, `disable-model-invocation` where confirm-gated, `argument-hint` where
arguments exist. Checklist-driven workflow bodies. Reference material split into
sibling files when SKILL.md would exceed ~150 lines. Each records a compatible
`stackVersion` range in frontmatter metadata.

### svelocity-convex

Add a table/query/mutation in THIS monorepo: schema in `packages/backend/convex/`,
wrapper in `packages/app-core`, reactive use in Svelte via convex-svelte. Validation:
`pnpm check` + convex dev codegen. Points at upstream Convex skills for generic
patterns — this skill is Svelocity-specific wiring, NOT a Convex tutorial.

### svelocity-auth

Convex Auth in this monorepo: `packages/auth` helpers, route guards (web), token flow
in the Electron/Capacitor shells (localStorage pattern per ADR 0002). Security
checklist. Provider-addition outline.

### svelocity-add-platform

Manual guide (until `svelocity add` in v1.1): copy the reference shell
(desktop/mobile/web), wire workspace deps, verify build. Ends with an explicit
**"update agent context"** phase:

1. Update `.svelocity/manifest.json` `targets[]`
2. Update AGENTS.md stack table + directory map
3. Update `.agents/README.md` if commands changed
4. Run `svelocity doctor` to validate the manifest

This keeps future agent sessions aware of the new platform without re-discovery.

### svelocity-alignment-audit

Cairno's alignment-audit adapted: manifest ↔ workspace ↔ docs claims. Confirm-gated
(`disable-model-invocation: true` + explicit user confirmation before running).
`full` / `quick` modes. Scored report written to `docs/audits/`. Conflict priority:
code > manifest > docs. Ships with `reference.md` (audit buckets) and
`report-template.md`.

### svelocity-changelog

Cairno's changelog skill adapted: `CHANGELOG.md` at root + root `package.json` version
bump. Collects conventional commits since the last tag (gh/git). Public-facing
register — no internal implementation detail. Ships with `reference.md` and
`changelog-template.md`.

## Manifest + CLI Wiring

**Manifest** (`.svelocity/manifest.json` + schema):

- `aiTargets: ["agents", "cursor"]`
- `skills: ["svelocity-convex", "svelocity-auth", "svelocity-add-platform", "svelocity-alignment-audit", "svelocity-changelog"]`
- Schema: enumerate known skills but keep the array open for user-added skills.

**CLI:**

- `create` — post-scaffold symlink generation; manifest gains `aiTargets` + `skills`
- `info` — already displays skills + aiTargets; verify rendering with real values,
  adjust if the empty state was assumed
- `doctor` — no new checks in v1 (Phase 8 territory); existing manifest-schema check
  covers the new fields

## Verification

1. **Unit:** manifest generation includes `skills`/`aiTargets`; symlink creation +
   copy-fallback behavior.
2. **E2e (gated, existing suite):** generated project has `.agents/skills/*`;
   `.claude/skills/*` links resolve; AGENTS.md is tokenized (project name substituted,
   no token residue — match the existing token syntax in build-template.mjs).
3. **Manual:** follow `svelocity-convex` in a fresh generated project → new table
   works; follow `svelocity-auth` → guard works; `svelocity-alignment-audit` dry run
   on the stack repo.
4. **Accuracy pass:** every path AGENTS.md references exists in the template output
   (scriptable grep check).
